# 统一词库与音频归档质量回归

日期：2026-11-17。基线为 v0.4.6 / `fbcfb9f`，候选为当前工作区。所有输入均为人工编写的合成场景，不含用户口述历史或个人词库。逐条输入、原始输出、检查结果和源码 SHA-256 见 [JSON 记录](context-regression-2026-11-17.json)。

## 方法与结果

| 层次 | 实际执行 | 基线 | 当前 | 结论 |
| --- | --- | --- | --- | --- |
| 首路 ASR | 缓存中的 Qwen3-ASR-1.7B-8bit；同一音频分别使用发布版和当前上下文构造 | 10/12 | 10/12 | 无新增断言失败，未证明热词准确率提升 |
| 自然整理 | 已启用的 `deepseek-flash`；发布版提示词/载荷与当前提示词/统一词库配对 | 24/24 | 24/24 | 语言、别名、普通词、数字、否定、用户改稿及指令边界通过 |
| 完整语音链路 | 当前 Qwen + 中英 SenseVoice 复核 + 文字 API + Opus 编码 | 未跑 | 12/12 | 最终正文通过；12例均产生非空音频事件 |

音频由 macOS `say` 的 Tingting、Samantha、Kyoko、Anna 生成并转换为单声道 16 kHz WAV。中英混说样例由三个语言片段串接，不能代表真人连续混说。ASR 模型复用全局缓存，没有下载或复制权重。文字 API 只接收合成文本；ASR 在本机执行。

自动检查使用语义锚点和禁止出现的词，允许自然改写；另外人工逐条查看当前输出。通过率是这些有限断言的通过率，不是字错率、总体成文质量分数或真人语音准确率。在线模型存在采样波动，本轮不是多次重复统计。完整链路没有发布版配对，不应据此宣称收益百分比。

## 实际发现并修正的问题

完整词库传入整理模型后，16例扩展测试中出现真实改义：输入“合同需要审验，暂时别发给客户”，词条为姓名“沈砚”、别名“审验”，候选输出将“审验”改为“沈砚”；基线保持正确。修订前输出已保存在 JSON 的 `discovered_regression` 中。

仅修改现行 `engine/polish.txt` 的证据边界：词条不是指令，aliases 不是机械替换表；普通词在当前语境成立时保留其含义，只有句意确实指向对应实体才纠正。没有增加程序替换、语义拦截或原文回退。随后新增8个保留场景，包括陈列/陈烈、罗列/罗烈、严谨/严锦、攀登/潘登，以及应当纠正姓名的正例，最终配对24例全部通过。

早期“研磨成粉”的断言曾误判合理改写“磨成粉”；校正为接受两者后重新评测。这个断言校正与上述真实改义分开记录，未把合法压缩当作质量退化。

## 保留的已知问题

- 首路 ASR 的姓名样例仍将“言墨/沈砚”识别成“研墨/沈燕”，基线与当前相同。
- 首路混说样例仍漏掉开头“请检查数据库”，基线与当前相同；模型将整段判为英语。本轮完整链路结合第二路后恢复该句，并保持中英原语言。
- 这些结果不能代替真实麦克风、实体快捷键、跨应用写入与 Windows CUDA 实机验收；本次没有替换在用应用包。

## 重跑

入口为 `scripts/evaluate-context-regression.py`，要求已有本机运行库及缓存模型。`--out` 指向被忽略的 `.local/` 目录；退出码非零表示候选出现新增断言失败，ASR 既有失败仍完整保留在报告内。

```sh
runtime/macos/python/bin/python3.12 scripts/evaluate-context-regression.py \
  --mode asr --baseline fbcfb9f --out .local/context-regression
```

文字与完整链路使用 `--mode text` / `--mode pipeline`，同时传入 `--settings`（只读现有 JSON 或 SQLite 设置）和 `--credential-helper`（本机模块提供 `load_key()`）。仅当文字 API 已启用才执行；凭证不进入仓库或结果文件。运行后检查 JSON 的 `summary`、`regressions` 与逐条输出，不能只看退出码。

与模型无关的事务、错误提示和真实 Electron 重启验证见 [架构与持久化说明](architecture/architecture-review-2026-11-17.md)。
