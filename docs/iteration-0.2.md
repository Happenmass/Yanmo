# 言墨 0.2 修订与验证

2026-10-21。Apple Silicon / 36 GB / macOS 26.6.2；本机开发构建，尚未公开分发。

## 体验修订

用户明确要求删除录音声音、缩小浮层、去掉不符合水墨风格的装饰动效，并让首页回归使用概览。本轮按此实现：

- 删除提示音设置与所有播放代码；音频引擎只建立输入采样，不创建混音器或输出节点，不提供麦克风监听回放。
- 浮层主体从 296×56 缩为 200×36 pt，使用平面墨色、细边框、轻阴影；没有渐变、缩放或弹跳。
- 声波只反映最近的真实麦克风测量；独立发布音量状态，避免首页随音量不断刷新。
- 首页为累计字数、音频时长、平均口述速度、活跃天数、近 20 周日历、快捷键指引和最近文稿。
- 统计来源是当前保留的本机文稿，包含导入音频；删除历史会改变统计。不显示未经测量的“节省时间”。

## 小模型与实际耗时

默认 LLM 改为 `mlx-community/Qwen3-4B-Instruct-2507-4bit`，约 2.28 GB 权重；ASR 保持已验证的 `mlx-community/Qwen3-ASR-1.7B-8bit`。复用用户全局 Hugging Face 缓存，旧 27B 权重没有删除。

选择依据：[Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507)注明该版本是非思考模型、Apache 2.0；[MLX 量化仓库](https://huggingface.co/mlx-community/Qwen3-4B-Instruct-2507-4bit)提供本机加载格式。

首次直接测试发现小模型会改写中文金额，因此单路转写先把数字替换为占位标记，检查输出标记的数量、顺序及新数字，再原样还原。违反校验时保留原文、不自动写入。词库明确别名在模型前替换，避免连锁替换。该保护只约束数字，不代表其他内容一定正确。

实测脚本 `scripts/benchmark.py`；结果 `model-benchmark-2026-10-21.json`：

- 10 个合成用例的关键内容检查全部通过，覆盖金额、否定、改口、术语、接口、提示词式口述、列表和中英混排。
- 首条含加载开销 5.186 秒，后续短文本整理中位数 1.017 秒。
- 11.56 秒音频样本：首次识别 1.198 秒、整理 1.282 秒；热运行识别 0.473 秒、整理 1.232 秒，共 1.705 秒。
- ASR 与小 LLM 同时驻留时，峰值 MLX 分配 5.851 GB；这不是应用总内存。
- 以上为有限样本，不是普遍准确率或固定时延承诺；与旧 27B 不是严格同条件对照。

## 采集链路修复

手动选择内建麦克风时，自检先在设置设备处失败；调整初始化顺序后暴露 `-10875` 初始化错误。Apple SDK 的 `AVAudioEngine.h` 明确说明访问 `mainMixerNode` 会创建并连接输出节点。移除这一多余输出链路后，输入采样和文件生成恢复；默认与指定设备的三秒自检均通过。当前只建立输入 tap，不创建输出节点。

## 快捷键补丁：纯修饰键无响应

2026-10-21，用户明确复现：进入“添加快捷键”后，单独左 Control 与 Control＋Shift 无响应。旧录制器仅处理 `keyDown`，这些按键产生的是 `flagsChanged`；全局监听也只对 Fn 处理此类事件，因此原有普通组合键测试未覆盖用户用法。

- 新增共享的 `ModifierChord` 状态处理，录制器和全局监听同时接入；保留左右键区别，全部松开后提交／触发一次。
- 按下时显示当前修饰键与“松开保存”说明；普通键或鼠标点击会取消本次纯修饰键触发，避免 Control＋C 等正常操作误录音。
- 配置新增可选的 `modifierKeys`，旧 Fn 与 Carbon 组合键记录保持可读；需要辅助功能的纯修饰键显示授权状态。
- `swift run YanmoChecks` 当前 7 项通过，新增检查覆盖单左 Control、Control＋Shift、双侧 Control、松开时机、普通操作抑制、切换组合及保存恢复。
- 原生 UI 回归 Control＋Shift＋D 添加和删除通过；构建与严格签名验证通过。用户已确认单独左 Control 与 Control＋Shift 均能通过实体按键添加；全局触发逻辑经共享状态回归检查，尚未单独确认这两组键的跨应用口述。
