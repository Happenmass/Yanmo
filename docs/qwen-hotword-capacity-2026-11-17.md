# 言墨 Qwen3-ASR 热词容量实测

日期 2026-11-17。试验只调用本机 Qwen3-ASR 1.7B 8bit 首路识别和言墨现有的 ASR 上下文构造。机器为 Apple M3 Max，`mlx-audio 0.4.6`，复用缓存模型快照 `a8379a2e2f9e313c9292cdf1af4055ab56d50d55`。这份记录保存实验设计、结果、实现规则和复跑入口。

## 数据与方法

- 49 段录音，约 220 秒。48 段为 macOS 本地合成，另有 1 段此前安装验收时的真人麦克风录音，从已归档 Opus 解码得到。
- 场景覆盖 AI 工具、代码编辑器、聊天、邮件、文档和通用。37 段含目标词，共 74 个目标词实例，12 段为没有目标词的负例。包含中文、英文、拼接混说和与热词近音的普通词。
- 每个场景使用固定的模拟词库和排序。32、64、128 总量主试验均按组内词占 3/4、全局词占 1/4 截取，通用场景全部取全局词。同一组中，各档词表逐级扩展。本次口述目标在词库中有不同排名，避免给每段录音预选正确答案。
- 只填规范词名，沿用产品当前 JSON 词条结构，备注和别名为空。无热词时按当前构造返回空提示，不加光标上下文；各注入档也不加光标上下文。整个 ASR 上下文在 32、64、128 词下分别约为 601–622、1123–1162、2223–2275 个文本 token。
- 主试验 49 段 × 4 档 × 2 轮，共 392 次。每档预热，固定随机种子打乱音频顺序和每条音频的条件顺序，串行调用。耗时包含文件读取、编码、生成和本地适配，排除模型加载、录音、第二路 SenseVoice、在线整理和写入。
- 64 词配额另对 41 段已分类音频加测 56+8 和 32+32，比较组内配额、共享配额改变后的召回。主试验中的 48+16 取同一子集对照。通用场景固定全局词，配额对比排除该场景。
- 目标词按规范拼写匹配，英文忽略大小写，要求英文词边界。无关词误入按**同一个场景完整候选词库**匹配输出，扣掉参考里确实说过的词，同一个词在一段里只记一次。因此无热词基线也在同一口径下评分。
- 召回和误入按第一轮逐录音统计，第二轮验证复现。延迟合并两轮并计算同音频、同轮相对基线的增量中位数。报告中另列目标在词表中的覆盖，及所有热词档都覆盖的目标子集。

## 复跑

在 Yanmo 根目录用内置 Python 运行 Git 忽略目录 `.local/qwen-hotword-capacity-2026-11-17/` 中的 `run.py`。主试验用默认参数，配额试验传 `--mode quota --totals 64 --repeats 1`。然后运行 `score.py` 和 `paired.py`。主试验与配额试验应串行运行。

`main-manifest.json` 和 `quota-manifest.json` 记录音频哈希、参考、逐场景确切词表和源码哈希。逐次推理输出和时长在 `main.jsonl`、`quota.jsonl`，评分在 `results.json`。真人录音留在本机忽略目录。

## 主试验结果

| 热词数 | 目标词召回 | 词表覆盖目标 | 无关词误入录音数 | ASR 中位 | ASR P95 | 同音频相对基线中位增量 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 0 | 38/74（51.4%） | 0/74 | 0/49 | 259 ms | 323 ms | 0 ms |
| 32 | 53/74（71.6%） | 35/74 | 1/49 | 488 ms | 587 ms | +233 ms |
| 64 | 59/74（79.7%） | 64/74 | 0/49 | 706 ms | 820 ms | +446 ms |
| 128 | 55/74（74.3%） | 69/74 | 0/49 | 1177 ms | 1350 ms | +917 ms |

- 196 个音频与条件组合的两轮转写逐字相同。32 词出现在聊天负例里的误入是「审验→沈砚」，64、128 词档在该样本保留了「审验」。各档中 12 段负例的误入录音数依次为 0、1、0、0。
- 32→64 词多认对 7 个目标、少认对 1 个，净增 6 个。64→128 词没有新增正确目标，4 个原本认对的目标丢失。三档词表共同覆盖的 35 个目标中，无热词、32、64、128 词分别正确识别 15、28、28、24 个。
- AI 工具组 13 个目标，无热词、32、64、128 词分别识别 5、8、9、9 个。真人试写中的「言墨」每档都在词表前列，基线输出「年末」，三个热词档皆输出「研末」，四档都未召回。

## 64 词的组内与全局配额

41 段已分类音频，62 个目标。用途分组与全局各自抽取固定排序的词，两类目标以去重后归属计数。

| 组内 + 全局 | 合计召回 | 组内目标 | 全局目标 | 无关词误入录音数 |
| --- | ---: | ---: | ---: | ---: |
| 56 + 8 | 44/62 | 34/42 | 10/20 | 0/41 |
| 48 + 16 | 48/62 | 34/42 | 14/20 | 0/41 |
| 32 + 32 | 46/62 | 33/42 | 13/20 | 0/41 |

建议首版把 64 设为总上限，有组时按 48 + 16 分配，某一边不足时由另一边补位，通用只用全局词。只消耗实际有候选的名额。固定配额的优先级依赖词库内容和排名，本轮用的是模拟排序，48 + 16 与 32 + 32 只差 2 个目标。真实词库覆盖、设备延迟和更丰富的真人语音仍需后续验证。64 词档比无热词增加约 0.45 秒首路推理，这个耗时应纳入产品取舍。

容量和延迟结果对应本轮 JSON 提示结构及测试机器。使用更长的词名、更长的光标上下文或不同 ASR 模型时，需要重新核对。样本里的词频排名是模拟值，真人样本只有一段。

## 实现规则

- 录音开始时保存目的应用类别和词库快照。词库界面可设为全局、AI 工具、聊天、邮件、代码编辑器或文档。已有词条和新手动词条默认全局。自动纠词的新词默认归到发起录音时的组。
- 词条列表上方的标签页可切换全部词条或单独类别。搜索在当前标签页内生效，空类别与搜索无结果分别提示。
- 当前组词优先覆盖同名全局词。组内和全局分别按累计命中、最近命中和新建时间降序。已分类应用取 **48 + 16**，一边不足时由另一边补位。未匹配到组时取 **最多 64 个全局词**。
- 普通口述成功产出正文后，检查当前组和全局里的所有适用词条。规范词在正文出现一次或多次，均只记 1 次。英文检查词边界，匹配忽略大小写和全半角差异，别名不计数。没进入本轮热词列表的词也能命中。导入、翻译、手动整理、取消和识别或整理失败不计数。关闭文稿历史时仍保存本地词频。计数衡量交付正文中的使用情况，可能受识别和整理结果影响。
- 桌面通过 `asr_hotwords` 分开传递最多 64 个规范词给首路识别。自然整理仍保留适用词条的备注和别名，SenseVoice 仍独立识别。SQLite v2 为旧词条补充范围及统计字段，旧数据从全局、零次开始。文稿、可选 Opus 音频和本次计数在同一事务保存，计数只更新命中的行。

## 回归入口

- `desktop/tests/hotwords.test.ts` 检查组内配额、双向补位、全局回退、去重、排序和词边界。
- `desktop/tests/controller.test.ts` 检查正常录音请求与计数、自动纠词归组，以及关闭历史时的统计持久化。
- `desktop/tests/store.test.ts` 检查 SQLite v1 升级、重启统计和命中行增量写入。
- `backend/test_pipeline.py` 和 `backend/test_server.py` 检查 ASR 与文字任务独立收词、显式空名单以及 64 词协议上限。
- `swift run YanmoChecks` 检查精确 Bundle ID、终端标题和潜在误分组。Electron 端到端测试覆盖词库标签切换、键盘导航、页内搜索和词条改组。

实现复测把六个场景的模拟词库交给当前 TypeScript 筛选器，产出的词表与原 64 词档逐项一致。经实际 HTTP 上传和后端路由调用本机 Qwen 后，**49/49 段首路转写与 64 词档原始输出逐字相同**。此复测使用测试替身承接正文整理，隔离了第二路 ASR 和文字 API。结果保存在同一本机目录的 `route-regression.json`。

验证通过 52 项桌面单测、28 项后端单测、46 项引擎单测、13 组 Swift 核心检查，以及 7 项 Electron 端到端检查。两项需要实机麦克风和系统输入的测试未启用。此次为源码和开发构建验证，在用安装包沿用上一轮版本。
