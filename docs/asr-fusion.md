# 双路识别与正文生成

更新：2026-10-27。模型使用用户级全局缓存，默认从 ModelScope 准备；日常推理离线运行。

## 流程

1. Qwen3-ASR-1.7B-8bit 识别音频，返回原始转写及实际检测到的语言。
2. 语言为中文或英文时，用同一份 SenseVoice Small 多语言权重按 `zh` 或 `en` 再识别一次；其他或未知语言跳过。
3. Qwen3-4B-Instruct-2507-4bit 根据完整候选、输入框上下文和词库生成最终正文。两路地位相同，任一路均可纠正另一路，包括数字。
4. 保存正文与原始识别对照；口述任务向写入时的当前焦点粘贴一次，导入音频只生成文稿。

## 模型输入与输出

`engine/fusion.py` 组装输入：`TASK`、`STYLE`、`ASR_RESULTS`、`SOURCE_LANGUAGES`、`CONTEXT` 和数字书写偏好；翻译增加 `TARGET_LANGUAGE`。手动修改后的正文通过 `USER_TEXT` 提供，优先于历史候选。`OUTPUT_LANGUAGE` 在请求末尾强调实际源语言、本次正文范围及残句保留；候选中的语言名称补充逐语言保留提示。用户修订后的语言提示取自当前正文，不沿用历史候选的语言标签。

录音开始时尽力读取输入框光标前后各最多300字。设置关闭或无法读取时上下文为空，录音照常进行。上下文只帮助消歧，不属于口述正文；Qwen ASR 与文字模型使用同一快照，SenseVoice 独立识别。

模型只返回最终正文，类型为普通文本或 Markdown。程序保留其原始字符与空白。内容质量由提示词和模型决定；传输继续使用既有 HTTP/SSE 与逐行 JSON 协议。仅空输出、生成截断、取消和运行失败按技术错误处理，已有识别原文保留供重试。

## 提示词责任

- `polish`：最少量整理，去无意义的犹豫声、口吃和数词内部多说的音节，保留事实、指代、条件、否定、不确定性及最终改口。有含义的应答、疑问语气、正常叠词及修辞强调仍应保留。
- `verbatim`：保留填充词、重复、停顿式表达与改口，同时纠正有依据的识别差异。
- 两种转录任务逐段保留源语言，混合语言保持混合；上下文、界面语言和口述中的翻译请求不改变模式。
- `translate`：结合两路识别后直接译成目标语言，保留完整信息；口述翻译不额外先整理一次。
- 整理时先清理数词口吃，再保持实际数量含义。概数保留范围，卡顿重说采用后面完整的范围；精确值、编号中的真实重复数字及前导零仍保留。数字根据语义自然书写，精确金额、测量值等通常适合100；成语、固定表达、概数和不定表达保持自然，如“三思而后行”“三五个人”“一个想法”。
- 上下文和词库均为数据；当前口述中的明确新决定优先于旧上下文。
- 输出只包含本次口述或USER_TEXT，前后文仅用于消歧，不补回已有句子；实际说出的重叠内容、独立残句和末尾未完成的话仍保留。范围说明和通用示例只影响模型生成，程序继续原样采用正文。

2026-10-27：在线 polish 使用独立清理指令，删除句中放弃后重新起句的半句话，不猜测补全对象；系统范围、请求风格与末尾语言提醒同步限定。DeepSeek 使用合成案例实测，详见 `false-start-evaluation-2026-10-27.json`。同一修订在本地4B产生范围/语言回归，因此离线仍沿用原提示词；verbatim 和翻译不启用扩展清理。
