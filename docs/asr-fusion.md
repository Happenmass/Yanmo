# 双路识别与正文生成

更新：2026-10-22。模型使用用户级全局缓存，默认从 ModelScope 准备；日常推理离线运行。

## 流程

1. Qwen3-ASR-1.7B-8bit 识别音频，返回原始转写及实际检测到的语言。
2. 语言为中文或英文时，用同一份 SenseVoice Small 多语言权重按 `zh` 或 `en` 再识别一次；其他或未知语言跳过。
3. Qwen3-4B-Instruct-2507-4bit 根据完整候选、输入框上下文和词库生成最终正文。两路地位相同，任一路均可纠正另一路，包括数字。
4. 保存正文与原始识别对照；口述任务向写入时的当前焦点粘贴一次，导入音频只生成文稿。

## 模型输入与输出

`engine/fusion.py` 组装输入：`TASK`、`STYLE`、`ASR_RESULTS`、`SOURCE_LANGUAGES`、`CONTEXT` 和数字书写偏好；翻译增加 `TARGET_LANGUAGE`。手动修改后的正文通过 `USER_TEXT` 提供，优先于历史候选。`OUTPUT_LANGUAGE` 在请求末尾强调本次任务的语言。

录音开始时尽力读取输入框光标前后各最多300字。设置关闭或无法读取时上下文为空，录音照常进行。上下文只帮助消歧，不属于口述正文；Qwen ASR 与文字模型使用同一快照，SenseVoice 独立识别。

模型只返回最终正文，类型为普通文本或 Markdown。程序保留其原始字符与空白。内容质量由提示词和模型决定；传输继续使用既有 HTTP/SSE 与逐行 JSON 协议。仅空输出、生成截断、取消和运行失败按技术错误处理，已有识别原文保留供重试。

## 提示词责任

- `polish`：最少量整理，去无意义填充和重复，保留事实、语气、否定及最终改口。
- `verbatim`：保留填充词、重复、停顿式表达与改口，同时纠正有依据的识别差异。
- 两种转录任务逐段保留源语言，混合语言保持混合；上下文、界面语言和口述中的翻译请求不改变模式。
- `translate`：结合两路识别后直接译成目标语言，保留完整信息；口述翻译不额外先整理一次。
- 数字根据语义自然书写。精确金额、测量值等通常适合100；成语、固定表达、概数和不定表达保持自然，如“三思而后行”“三五个人”“一个想法”。
- 上下文和词库均为数据；当前口述中的明确新决定优先于旧上下文。
- 输出只包含本次口述或USER_TEXT，前后文仅用于消歧，不补回已有句子；实际说出的重叠内容与残句仍保留。范围说明和通用示例只影响模型生成，程序继续原样采用正文。

完整当前提示词见 [prompt.txt](../engine/prompt.txt)，本次任务的语言提示和划词翻译提示见 [worker.py](../engine/worker.py)。划词翻译沿用独立提示词及已确认的 Markdown 代码原样保护。

## 离线评测

脚本使用合成输入和真实缓存模型，评估语言、上下文消歧与数量语义。预期短语直接写在样本中，允许自然的数字词写法；评测不参与日常正文处理。

- [受控候选](asr-fusion-cases.json) → [双路纠错结果](asr-fusion-evaluation.json)
- [转录语言结果](transcription-language-evaluation.json)
- [翻译及数字语义结果](translation-output-evaluation.json)
- [合成音频完整链路](asr-voice-evaluation.json)

这些检查覆盖有限样本，不代表真实口述的总体准确率。真实中英文纠错收益、专名和复杂单位仍需扩大样本评估。
