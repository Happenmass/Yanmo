# 言墨 0.1 开发预览验证

日期：2026-10-21。环境：Apple Silicon / macOS 26.6.2 / Swift 6.3.2。

## 已验证

- `scripts/build.sh` 成功构建 `dist/言墨.app`，原生应用可启动，ad-hoc 签名严格校验通过。
- 主窗口、文稿、词库、设置已通过真实应用界面检查；视觉按照已确认的 Image Gen v1 实现。
- 从原生文件选择器导入本机 11.56 秒语音样本，经 Qwen3-ASR 与本地 MLX-LM 生成 66 字文稿；原文保留、正文可编辑，历史在应用重启后存在。
- 词库新增「言墨」并在应用重启后保留。
- `swift run YanmoChecks`：3 项核心检查通过，覆盖原文/编辑稿/词库持久化、文件权限、损坏源文件保留、应用类别判定。
- `python3 -m unittest discover -s engine -v`：4 项检查通过，覆盖口述命令和上下文的数据边界、多候选传递、未完成推理拒绝、缺失权重缓存拒绝。
- Python 源码编译、Shell 语法检查通过。
- 用户授权并完成系统身份验证后，辅助功能重新登记到当前构建签名，Fn 监听已启用。
- 麦克风由用户在系统提示中允许；实际录音启动、计时更新，随后通过界面结束并取消处理，提示临时录音已删除。

## 交互实测

- 用户确认实体 Fn 可唤起浮层，口述能进入本地 ASR/LLM 并保存文稿；两次报告文本编辑未出现文字，应用记录的目标均为 ChatGPT。
- 已暂时退出同时监听 Fn 的 Typeless，排除同键竞争；快捷键在主运行循环回调中同步捕获目标，并以 AX 输入控件所属应用确定目标。
- 写入边界的独立自检先复现：调用激活文本编辑后焦点仍为 ChatGPT，原本的前台切换要求使验证失败。
- 修复后优先写入捕获的原 AX 控件，再读回比对预期全文；实际文本编辑正文出现「言墨写入验证：预算三千五百元，周五交付，不是周四。」，自检通过。
- 黑墨浮层显示目标应用名称。用户确认修订后的实体 Fn 口述可写入文本编辑；AX 观察也读到实际新增的口述句子。
- ChatGPT 首次复测仍失败：已记录「输入框已接受写入，但无法读回核验」，原直接 AX 路径没有产生用户可见输入。
- 当前实现对仍在前台的目标优先标准粘贴；缺失 AX 光标选区也允许在核对目标控件后粘贴。背景原生控件保留直接 AX 写入和读回核验。
- 失败或结果未核实时不再主动打开主窗口，文稿保存写入说明；无法读回的粘贴不虚报「已写入」。
- 用户最终确认 ChatGPT 输入框可正常填入「这是输入测试。」；文本编辑与 ChatGPT 两条实体 Fn 链路均通过人工验证。
- 自动化工具不能模拟实体 Fn，且禁止直接访问当前 ChatGPT 应用；ChatGPT 的最终验收由用户完成，没有使用其他接口代操作。

## 开发限制

- 原生应用通过外部 Python 环境运行 MLX，尚未打包独立推理运行时、制作安装包、公证或发布公开仓库。
- 运行时只检查本地模型，不执行模型下载。本次复用已有全局缓存，没有复制或下载权重。
- 缓存检查与实际推理分开；资源占用和延迟随所选模型变化。当前为单 ASR，未实现多引擎并行。
- Command Line Tools 不包含 XCTest / Swift Testing，因此核心测试采用独立的 Swift 检查程序。
- TCC 授权曾指向旧 ad-hoc 构建签名；通过系统界面移除旧记录、重新添加当前应用解决，没有直接修改权限数据库。
